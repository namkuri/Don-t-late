# order — 발주 접수 (시공 전 의무 절차)

> D-060(발주 커밋 ≠ 납품 커밋) + D-070(MDA 게이트)의 실행 절차. S-050~065 위반 재발 방지가 목적.
> **어떤 급한 지시든 이 절차(1~2분)를 시공보다 먼저 한다.**

## 입력
사람 지시 원문(레인 자동 판별: 시스템=S / 오디오=AU / 아트=A / 콘텐츠=C).

## 절차

1. **번호 채번**: 해당 대장(planning/orders/{system,audio,art,content}.md)의 마지막 번호 +1.
   번호 충돌 시 선발 유지 — 후발이 재번호(레인 교차 충돌이면 후발을 자기 레인 접두어로).
2. **시각**: `date "+%Y-%m-%d %H:%M"` 실행값만 사용 (타임스탬프 손기입 금지 — §3-13 반복 실수).
3. **대장 append** (봉투 최소형 — D-060):
   ```markdown
   ## {ID} · 발주 {시각} → {수행자} ({제목})

   요구 ({사람} 원문): {불릿 요약 — 원문 디테일 보존}

   수용기준: {관찰 가능한 판정 기준 1~3줄}
   MDA 판정 (D-070): 강화/약화/무관 — {한 줄 근거}. 무관이면 후순위 후보 명시.
   ```
4. **[발주] 커밋·push 먼저**:
   ```bash
   git add planning/orders/<대장>.md && git commit -m "[발주] {ID}: {제목}" && git push origin main
   ```
   post-commit 훅의 📦 알림 = 팀 착수 예고. **이 push 전에는 코드 파일을 만들지 않는다.**
5. 타 레인(정수님·민지님)행 발주면 디스코드로 요청체 안내 발신(`python scripts/discord_notify.py`).
6. 그 다음에야 시공 시작. 결과·코드는 별도 납품 커밋(→ /deliver 스킬).

## 금지
- 발주 기록과 결과를 한 커밋에 뭉치기 (위반 이력: S-050~A-006 15건 — 2026-07-28 적발).
- MDA 판정 생략 (기획 확장기 분산 방지 장치).
